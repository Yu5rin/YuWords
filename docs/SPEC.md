# YuWords 仕様書 v0.3（実装は v0.3.0）

送信メールから頻出語を抽出し、Microsoft IME のユーザー辞書を作るツール

作成日: 2026-10-31
参照実装: Python（Sudachi）で検証したプロトタイプ。抽出ロジックの正解はこれ（社内のデータで試したものなので、リポジトリには含めない）

---

## 1. 目的

PCを乗り換えるとMicrosoft IMEの予測変換（学習履歴）がリセットされる。学習履歴は非公開形式で移行できないため、**自分が実際に書いた文章（送信メール）から頻出語を抽出し、ユーザー辞書に登録する**ことで、乗り換え直後から社内用語・部署名・案件名などが変換候補に出る状態を作る。

辞書はテキストで書き出せるため、一度育てた辞書は次のPCにもそのまま持っていける。

### やらないこと

- キー入力の横取り（TSF/フック）による履歴収集。キーロガー同等になり会社PCで使えないため
- IME学習ファイル（IMEJPフォルダ）の直接解析・書き換え
- ネットワーク通信。データはすべてローカルで完結させる

---

## 2. 動作環境・技術構成

| 項目 | 内容 |
|---|---|
| OS | Windows 10 / 11（新しいMicrosoft IME） |
| 言語・UI | C# / .NET 8、WinForms |
| メール取得 | Outlook クラシック版のCOM（`Microsoft.Office.Interop.Outlook` か late binding）。新しいOutlookはCOM非対応のため対象外 |
| 形態素解析 | NMeCab ＋ UniDic（品詞体系がSudachiと同じUniDic系のため、参照実装の判定条件をそのまま移植できる） |
| IME連携 | `IFELanguage`（よみ→変換結果の取得）、`IFEDictionary`（ユーザー辞書への直接登録）。どちらもmsime.hのCOMインターフェース |
| 配布 | 単一フォルダのポータブル版（インストーラ不要）。設定は `%APPDATA%\YuWords\` |

参照実装（Python）で、新しいIMEでも `IFELanguage`（ProgID `MSIME.Japan`）が動作することは確認済み。`IFEDictionary` は未検証のため Phase 3 の最初に検証する。

## 3. 処理フロー

```
[取り込み] Outlook送信済みアイテム
    ↓
[前処理] 引用除去 → 署名・定型行の分離 → 文字正規化
    ↓
[抽出] 形態素解析 → 名詞の連結（複合語化）→ 前後トリム → ノイズ・一般語の除外
    ↓
[よみ生成] カナ→ひらがな、英数字→アルファベット読み、要確認判定
    ↓
[集計] 出現メール数でカウント、IMEの変換結果を参考取得
    ↓
[確認画面] 一覧で取捨選択・よみ修正
    ↓
[出力] IMEへ直接登録 or 辞書ツール用テキスト出力
```

## 4. 機能仕様

### 4.1 取り込み（メール読み込み）

- 既定フォルダの「送信済みアイテム」（`olFolderSentMail = 5`）を送信日時の新しい順に読む
- 設定項目: 対象期間（既定180日）、最大件数（既定2000件）
- 件名＋本文（`Body`、プレーンテキスト）を対象とする
- MailItem以外（会議出席依頼など）は飛ばす。読めないアイテムは例外を握りつぶして続行
- 読み込みは別スレッドで行い、進捗（件数）を表示。キャンセル可能にする

### 4.2 前処理

**引用・転送の除去**: 次のいずれかに一致する行が出たら、以降を捨てる。

- `-----Original Message-----` / `元のメッセージ`
- `_____`（アンダースコア5個以上だけの行。Outlookの返信区切り）
- 行頭が `From:` `差出人:` `送信者:` `送信日時:` `Sent:`（全角コロン含む）
- `On ... wrote:` / `yyyy/... 書きました`

あわせて `>` `＞` で始まる行と空行は除外する。

**署名・定型行の分離**: 全メールの行ごとに「その行が出現したメール数」を数え、`max(3, 全件数 × 10%)` 以上の行を署名・定型行とする。

- 本文側の集計からは除外する（1通ごとに署名分の回数が加算されるのを防ぐ）
- ただし署名行から抽出した語も候補に残し、出現数は「その行が出たメール数」とし、「署名」フラグを付ける（自分の部署名・会社名は署名にしか出ないことが多いため）

**文字正規化**: NFKC正規化を行う。半角カナの濁点が `シ゛` のように別文字になるケースがあるため、`゛`→U+3099、`゜`→U+309A に置換してからNFKCをかける。これで `ＸＹＺ`→`XYZ`、`ﾊﾟｲﾌﾟｸﾘｯﾌﾟ`→`パイプクリップ`、`シ゛ユウタク`→`ジユウタク` に揃う。

### 4.3 抽出

行単位で形態素解析し、以下のトークンが連続する区間を1つの複合語としてまとめる。

- 名詞（数詞を除く）
- 接尾辞・名詞的（部・課・係・室・様 など）

区間が途切れたら、次の順でトリムしてから候補化する。

- 先頭から外す: 接尾辞、ひらがなだけのトークン、1文字の助数詞可能名詞（「3台出荷」→「出荷」）、前置き語（通り / とおり / 以下 / 下記 / 上記 / こと / 添付 / 本件 / 今回 / 本日 / その後 / いつも / 皆様 / 各位）
- 末尾から外す: 様 / さん / 殿 / 各位 / 等 / 宛

候補から除外する条件（ノイズ）:

- 2文字未満、ストップワード（お世話 / よろしく / お願い / 確認 / 連絡 / 件 / 以上 / 皆様 / 各位 / 本日 / 明日 / 今回 / 対応 / ご確認 / 宜しく）
- 英数字・記号だけ、ひらがなだけ
- 括弧・鉤括弧・スラッシュ・コロン・読点などの記号を含む
- 15文字超（設定値 `MaxCompoundLength`）
- **辞書にある1語の普通名詞**（変更・完了・添付など）。登録しても効果がないため

**英字始まりの複合語の分割**: トリム後の先頭トークンが英数字なら、それを除いた部分も別候補にする（`XYZ設検課` → `XYZ設検課` と `設検課` の両方）。

**NMeCab＋UniDic への移植で足した扱い**（Phase 1 で確定。Sudachi と結果を揃えるため）:

- 辞書は UniDic 2.1.2（unidic-lite 1.0.8 同梱のもの）。よみは仮名形（`kana`）を使う
- MeCab は空白を読み飛ばして前後の語をつなげるため、空白で区切って解析し、間を語の切れ目とする（`XYZ設検課 山田` が1語にならないように）
- 未知語（英数字・カタカナ・漢字だけのもの）は、品詞にかかわらず名詞として扱う。MeCab は文脈で `XYZ` を感動詞などにすることがある。数字だけの未知語は数詞として扱い、名詞にはしない
- UniDic は単独の漢字（`電` `推` など）を「記号,一般」にすることがある。漢字1文字の記号も名詞として扱う
- 未知語は仮名形を持たない。表記が仮名だけならそれをよみとする（`ジユウタク`→`じゆうたく`）。漢字を含めばよみは空欄になる
- UniDic は短単位で区切るため、Sudachi の C モードでは1語の普通名詞（一般語として除外）になる語が、複合語として候補に残ることがある

### 4.4 よみ生成と要確認判定

- 通常トークン: 辞書の仮名形（カタカナ）をひらがなに変換
- 英数字トークン: 1文字ずつアルファベット読み・数字読みに変換（`XYZ`→`えっくすわいぜっと`、`2`→`に`、`-`→`ー`）。変換表は参照実装の `ALPHA_READING` / `DIGIT_READING`
- 結合後のよみが `[ぁ-んー]+` に一致しなければ、よみは空欄（不明）とする

次のいずれかに当てはまる語は「要確認」とする。

- 未知語（辞書にない語）を含む
- 英数字を含む
- 漢字1文字のトークンが2つ以上ある（「特／意／課」のように辞書にない略語が分割されたもの。よみは字ごとの推測）
- 人名を含む（「東海林→とうかいりん」「小鳥遊→ことりあそび」のような推測ミスが多い）
- よみが空欄

### 4.5 集計

- 回数は「その語が出現したメールの数」で数える（1通に何度出ても1）
- 既定で3通以上（設定値 `MinMails`）の語を候補にする
- 各候補について `IFELanguage.GetConversion(よみ)` の結果を取得し、「IMEの変換結果」と「IMEで変換可（結果が語句と一致）」を参考情報として持つ。**除外条件には使わない**（変換できる語でも予測変換の候補に出したいため）

### 4.6 確認画面（メイン画面）

候補一覧をグリッドで表示する。

| 列 | 内容 | 編集 |
|---|---|---|
| 登録 | チェックボックス。初期値は「要確認でない」かつ「よみあり」ならON | 可 |
| 語句 | 抽出された語 | 可 |
| よみ | 生成されたよみ。空欄・要確認は色付け | 可 |
| 品詞 | 既定は名詞。人名・地名・固有名詞を選べる | 可 |
| 出現メール数 | | 不可 |
| 分類 | 複合語 / 普通名詞 / 人名 / 地名 など | 不可 |
| 署名 | 署名・定型行由来なら印 | 不可 |
| IME変換結果 | 参考 | 不可 |
| 要確認 | 印 | 不可 |
| 例文 | その語を含む本文の1行（よみ判断の手がかり。ホバーで表示でもよい） | 不可 |

操作:

- フィルタ: 要確認のみ / 署名由来のみ / IMEで変換不可のみ / 登録チェック済みのみ、語句の部分一致検索
- 並べ替え: 各列ヘッダクリック
- 一括操作: 選択行の登録ON/OFF、選択行を除外リストへ追加
- よみを編集した行は要確認を解除し、登録をONにする
- 右クリック「除外リストに追加」: 次回以降の抽出結果に出さない（個人的な語や不要語の恒久除外）

### 4.7 出力

- **IMEへ直接登録**（Phase 3）: 登録チェックの付いた行を `IFEDictionary.RegisterWord` でユーザー辞書に登録。既に同じ語・よみがあればスキップ。結果（登録数・スキップ数・失敗数）を表示
- **テキスト出力**: Microsoft IME ユーザー辞書ツールの「テキストファイルから登録」形式
  - 文字コード UTF-16 LE（BOM付き）、改行 CRLF
  - 1行目 `!Microsoft IME Dictionary Tool`
  - 以降 `よみ<TAB>語句<TAB>品詞`
- **CSV出力**: 全候補をUTF-8（BOM付き）で出力（Excel確認用）
- 出力先ファイルが開かれていて書けない場合は、`ファイル名_yyyyMMdd_HHmmss.拡張子` に別名保存して通知する

### 4.8 永続データ

`%APPDATA%\YuWords\` に保存する。

| ファイル | 内容 |
|---|---|
| `settings.json` | 対象期間、最大件数、最低出現数、最大文字数、署名判定割合、ストップワード・前置き語の追加分 |
| `excluded.json` | 除外リスト（語句単位） |
| `registered.json` | 登録済みリスト（語句・よみ・登録日時）。次回実行時は登録済みの語を「登録済み」として薄く表示、または非表示にする |
| `dictionary_backup.txt` | 登録のたびに更新する、これまで登録した全語のテキスト（IME取り込み形式）。**新PCへの持ち出し用** |

`dictionary_backup.txt` の保存先は設定で変更可能にする（OneDriveなどに置けば新PCでそのまま取り込める）。

## 6. 非機能要件

- メール本文・抽出結果は外部に送信しない。ログにも本文を残さない
- 1000通程度の解析が1分以内に終わること（目安）
- 処理中もUIが固まらないこと（解析はバックグラウンド、進捗表示とキャンセル）
- Outlookが起動していない、クラシック版がない、などの場合は分かりやすいメッセージを出す

## 8. 既知の課題・今後の検討

- 社内略語のよみは原理的に推測しかできない。確認画面での手修正が前提
- 人名のよみは誤りが多い。Outlook の連絡先のふりがなで補う機能を付けた（9章）。会社のアドレス帳（GAL）のふりがなは未対応
- 複合語が長くつながりすぎるケース（「標準コアユニット月次報告」など）は、確認画面で語句を編集して対応。自動分割は将来検討
- 予測変換の並び順（学習履歴）までは再現できない。目的は「候補に出ること」

## 9. 実装で決めたこと（v0.1.0）

仕様に書かれていなかった点、実装して変えた点をまとめる。

### Phase 2（確認画面・出力）

- 一覧の色: 推測のよみは黄、よみ不明は赤、IME で変換できる語の変換結果は緑、登録済みの語は灰色
- キー操作: Space で選択行の登録切り替え、Delete で除外リストへ追加
- 登録チェックを付けたまま登録も出力もしていない語があるとき、読み込み直し・終了の前に確認する
- 「IME 用テキストに出力」した語も登録済みとして扱い、`registered.json` と `dictionary_backup.txt` を更新する（ユーザー辞書ツールで取り込む前提のため）
- 品詞は 名詞 / 人名 / 地名 / 固有名詞 から選ぶ

### Phase 3（IME への直接登録）

- `IFEDictionary` は ProgID `MSIME.Japan` のオブジェクトから取得し、`Open(NULL)` で既定のユーザー辞書を開く。定義は Windows SDK の msime.h に合わせた
- 品詞番号は `GetPosTable` の表（名前は Shift_JIS）から引く。引けなければ msime.h の値（名詞 100・人名 106・地名 109・固有名詞 118＝その他の固有名詞）を使う
- 登録前に `ExistWord` で同じ語・よみ・品詞を確かめ、あれば「既にあったもの」として数える（登録済みリストには入れる）
- `Open` できない IME では何も登録せず、IME 用テキストへの出力とユーザー辞書ツール（`IMJPDCT.EXE`）の起動に切り替える
- 設定の「登録済みの語」で、IME からの削除（`RegisterWord(IFED_REG_DEL)`）と一覧からの除外ができる
- 新しい PC での復元用に、IME 取り込み形式のテキストを選んで一括登録できる

### Phase 4（取り込み元の追加）

- フォルダ: `.md` / `.txt` を1ファイル1文書とする。隠しフォルダ（`.obsidian` など）は読まない。ファイル名（ノートの題名）も1行として扱う
- Markdown は front matter・コードブロック・コメント・画像・URL・記号を外す。`[[リンク|別名]]` は表示される側の文字、タグ（`#設計審査`）は `#` だけ外して語として残す。表のセルは別の行として扱う
- 文字コードは BOM があればそれに従い、無ければ UTF-8、読めなければ Shift_JIS
- Excel・CSV: 選んだ列のセルを1つずつ文書とする（出現数は「その語が出た行の数」）。xlsx は Excel なしで読む（値のみ、ふりがなは除く）
- メール以外では、出現数の列名を「出現文書数」などに、署名の列名を「定型」に変える。分離の仕組みは署名と同じ
- メールと違い、引用の判定はしない

### 追加した機能

- **連絡先のふりがな**: Outlook から読み込むとき、連絡先の姓・名のふりがな（`YomiLastName` / `YomiFirstName`）で人名のよみを置き換え、要確認を外す（8章の検討課題）。設定で切り替えられる
- **今の一覧に追加**: 別の取り込み元を今の一覧に足し、全文書を合わせて数え直す。前の一覧での選択（登録・語句・よみの修正・品詞）は引き継ぐ
- **ポータブル版**: `tools/publish.ps1` で .NET ランタイム同梱の単一フォルダ版と zip を作る

## 10. v0.2.0 で足したこと

### よみの精度

- IME の `IFELanguage.GetPhonetic` で表記からよみを取り、「IMEのよみ」として並べる。形態素解析の推測と食い違う語は要確認にする（連絡先・前回の修正・ルールで決まったよみは除く）。よみが作れなかった語は IME のよみを推測として使う。英字が全角のまま残ったよみは使わない
- 同じよみで表記が違う候補（表記ゆれ）に印を付ける
- 4語以上の複合語の先頭側・末尾側の部分（2語以上）を作り、2種類以上の複合語に共通するものを「部分語」の候補にする。出現数は単独・部分のどちらかで出たメール数
- よみのルール（「表記=よみ」）を複合語の一部にも使う（連続するトークンの長いものを優先）。ルールで決まった部分は要確認の判定から外す
- 確認画面で直したよみを `learned.json` に覚え、次回の抽出で同じ語に使う
- 人名のよみ: 会社のアドレス帳（Exchange GAL）のふりがな（PidTagAddressBookPhoneticSurname / GivenName）でも補う。候補の名前で始まる人だけを調べ、件数（5万）と時間（60秒）に上限を設ける。同じ表記によみが2通り以上ある名前は補わない。既定は OFF

### 確認作業

- おすすめ度: log2(出現数+1)、IME で変換できない語は 3 倍、部分語は 0.8 倍、定型文は 0.8 倍（変換の可否は見ない）。上位 2 割 ★★★・次の 3 割 ★★・残り ★。読み込み直後はこの順に並べる
- 確認済み（値の変更・Enter キーで付く）と保留（`held.json`。選んだよみ・品詞のまま次回以降も保留）。「未確認のみ」「保留中も表示」で絞り込む
- 元に戻す（Ctrl+Z、100 操作まで）。除外は確認なしで行い、元に戻せるようにした
- 途中の状態を `session.json` に自動保存し、起動時に再開する。再開した一覧に「今の一覧に追加」したときは、元の文書を持っていないので数え直さず、新しい候補を足す
- よみを直したら IME の変換結果を取り直す
- 語を手で追加する画面（Ctrl+N）。クリップボードの1行（60文字まで）を入れ、よみは IME に問い合わせて提案する
- 文字の大きさの設定。列の幅・行の高さは文字の大きさと画面の拡大率に合わせる（拡大率の違うモニターへ移ったときも）

### 短縮よみ・定型文

- 2語以上で、よみが5文字以上の語に、各語のよみの頭の1音（拗音は2文字）をつなげた短いよみを提案する
- 1語に別のよみを付けられる（「、」区切り）。登録・出力・持ち出し用辞書には本来のよみと別のよみの両方を入れる
- 署名・定型行のうち、日本語を含み 6〜60 文字のものを、出現数の多い順に最大 30 件「定型文」の候補にする。品詞は「短縮よみ」（JPOS_TANSHUKU = 913）、よみは自分で入れる

### 登録済みとの照合・持ち出し

- 読み込み時に `IFEDictionary.GetWords`（ユーザー登録分）で IME のユーザー辞書を読み、同じ語・よみを「登録済み」にする（設定で切り替え）
- 設定から IME のユーザー辞書の語をすべて登録済みの一覧に取り込める（YuWords 以外で登録した語も持ち出し用辞書に入る）
- 持ち出し用辞書は中身が変わるたびに、前の版を設定フォルダの `backups` に日時付きで残す（新しい順に 10 個）
- 初回起動時に、前の PC から移ってきた人向けに持ち出し用辞書からの登録を案内する
- 登録済みの語の CSV 書き出し（語句・よみ・品詞・登録日）と、CSV（見出しの「語句」「よみ」「品詞」で列を判断。見出しが無ければ 1〜3 列目）からの登録

### 取り込み元

- フォルダで Word（.docx。段落ごと）と PowerPoint（.pptx。スライド順、ノートも）を Office なしで読む。`~$` で始まる一時ファイル、開けないファイルは飛ばす
- フォルダは「最近 N 日以内に更新したファイルだけ」にできる
- Outlook は「前回以降の新しいメールだけ」読める。このときは登録済みの語を一覧に出さない

- 表の下に例文の欄を置き、選んだ語の例文（違う行を最大 5 件）を語を強調して出す
- 設定を保存したとき、読み込み済みの文書があれば今の設定で数え直せる（読み込み直さない。選択は引き継ぐ）。途中保存から再開した一覧は元の文書を持っていないので数え直せない

- 設定で頻度（しない／毎週月曜／毎月1日）と時刻を選ぶと、`schtasks` でタスク「YuWords 新しい候補のチェック」を登録・解除する

- 通知をクリックすると `YuWords.exe --new` で開き、新しいメールだけを読み込む（途中の一覧があればそれに足す）

## 13. v0.5.0 で足したこと

- 1章の「ネットワーク通信をしない」の例外として、新しい版の確認と配布物の取得だけを行う（GitHub の Releases API）。送るのは版の問い合わせだけで、利用者のデータは送らない。設定で止められる
- 自動更新: 起動時（1日に1回まで）または手動で確かめる。GitHub の最新リリースの `YuWords-x.y.z-win-x64.zip`、社内の共有フォルダにあるいちばん新しい配布物、または手元の zip から更新する
- 会社の環境: Windows のプロキシ設定とログイン中のアカウントの認証情報を使う。社内のルート証明書は Windows の証明書ストアのものを使う。管理者権限は要らない（アプリのフォルダに書き込めることを確かめる）
- 差し替え: 配布物の SHA256 を確かめ（GitHub は digest か本文の表、共有フォルダは `zip の名前.sha256` があれば）、`%LOCALAPPDATA%\YuWords\update` に展開して Zone.Identifier を外す。YuWords を閉じたあと、cmd と robocopy だけのバッチで上書きして起動し直す（`--updated` / `--update-failed`）。開発中の実行（bin\Debug・bin\Release）では差し替えない
- IME のユーザー辞書を使う処理（読み取り・登録・削除・確認）は、YuWords.exe を `--ime-worker` で別のプロセスとして起動して行う。IME の品詞表は読まず、品詞番号は msime.h の定数を使う。登録する語は 0 で埋めた領域に書き、詰める・詰めないどちらの並びでも同じ位置になる項目だけを使う。読み取りは文字の位置が領域の中にあるかを確かめてから読む
